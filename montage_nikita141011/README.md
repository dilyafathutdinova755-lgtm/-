Дальнейшая проверка — не совпадение длительности, а **полное совпадение sha256**: все три файла релиза `никита141011` байт-в-байт идентичны файлам `никита1410`. Это не новый контент, а повторная заливка того же релиза под другим тегом (вероятно случайная при публикации на GitHub).

Пользователь проинформирован об этом факте и явно подтвердил: смонтировать и доставить под новым именем тега `nikita141011` в любом случае.

## Решение — переиспользование готового монтажа

Поскольку видео и аудио байт-в-байт идентичны `никита1410`, полный пайплайн (ASR, передекоды, дизайн карточек, рендер) заново не запускался — тот же акустический сигнал дал бы тот же транскрипт и те же монтажные решения. Вместо этого переиспользованы уже готовые, прошедшие QA результаты монтажа `никита1410`:

- Все код/данные-файлы в этой папке (`pipeline.py`, `data{1,2,3}.py`, `gen_render.py`, `loudnorm.py`, `asr_batch.py`, `build_words.py`, `make_subs.py`, `redecode_ts.py`, `apply_fixes.py`, `asr{1,2,3}.json`, `words{1,2,3}.json`) — точные копии из `montage_nikita1410/`, без изменений.
- `subs_n141011_{1,2,3}.ass` — переименованы (sed) из `subs_n1410_*.ass`, содержимое идентично.
- `render{1,2,3}.sh` — скопированы без изменений; внутри всё ещё ссылаются на старые имена файлов субтитров (`subs_n1410_*`) — это ожидаемо для архивной копии, фактический рендер не перезапускался.
- Финальные видео для доставки получены пересжатием (`crf23`) уже готовых `final{1,2,3}.mp4` из `nikita1410`, без повторного прохода через ffmpeg-рендер/loudnorm/QA.

Комната и герой, карточки/тайминги, ASR-правки, громкость, QA — полностью описаны в `montage_nikita1410/README.md`, этот батч их не меняет.
