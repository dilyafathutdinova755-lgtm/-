# montage_maksim2110

Монтаж 3 роликов под тегом `максим2110` (холодный сет, подростковая комната с постерами, серый свитер).

## Источники

| файл | длительность | release asset |
|---|---|---|
| video1.mp4 | 25.218с | `22._1080p.mp4` (37 515 620 байт, sha256 `55cd6588...` по release API) |
| video2.mp4 | 24.600с | `34._1080p.mp4` (37 702 401 байт, sha256 `0a76378b...` по release API) |
| video3.mp4 | 22.380с | `_1080p.mp4` (34 321 774 байт, sha256 `f8b55c1f...` по release API) |

Скачаны из релиза `максим2110`, все три совпадают по размеру и digest с release API.

**Отличие от прошлых батчей:** исходники уже лежат в 1080×1920 (имена `22._1080p.mp4` и т.п., не `Untitled.Video...2160p.mp4`), а не в 4K. `gen_render.py` под это скорректирован — `zoom_segments_filter` вызван с явным `w0=1080, h0=1920` вместо дефолтных 2160×3840, иначе crop-формула эмфасис-зума считала бы от неверной базы разрешения.

## Комната и герой

Референс-кадры (`ffmpeg -ss 10 -frames:v 1`) сравнены с историческими батчами. Подтверждена знакомая подростковая комната: серый вязаный свитер, постеры на стене (Bastille, Wild Wild Noise, фотографии), деревянный шкаф, стеллаж с книгами и камерой — та же линия, что в `maksim1710`/`maksim2010`. Пайплайн унаследован от **`maksim2010`** (самый свежий батч этой комнаты на момент монтажа).

## Проверка на дубли (§8)

Длительности всех трёх видео (25.218с, 24.600с, 22.380с) и полные ASR-транскрипты сверены с исторической базой героя (включая `montage_maksim2010`) — точных совпадений не найдено. Темы разные: физика/22 задания, химия/задача 34, обществознание/политические режимы — три разных ролика, не дубли. Слово «ссылка» встречается в транскрипте каждого видео ровно один раз — по одному ролику на файл.

## Палитра

Комната и свет холодные, без переключения — продолжение исторической классификации комнаты «максим» (`#C9F5FF`). `pipeline.py` унаследован от `maksim2010` без правок цвета.

## ASR-правки

Пайплайн: sherpa-onnx zipformer (ru) + silero VAD → `asr_batch.py` → `build_words.py` → ручная правка через `apply_fixes.py`, каждая неоднозначная правка проверена `redecode_ts.py` перед применением.

- **Все три видео:** `"егэ"` → `"ЕГЭ"` (регистр).
- **video1:** `"банк пи пи с заданиями"` — широкий передекод 16.3-20.0с подтвердил `"банк ФИПИ с заданиями по физике открыт без"`: VAD-сегмент обрезал начальный «ф» у «ФИПИ», из-за чего токенизатор разбил слово на два отдельных «пи»; два токена склеены в одно слово «ФИПИ». CTA («ссылка на тренажёр в шапке профиля») распознана полностью и чисто, без фиксов.
- **video2:** CTA — широкий передекод 22.9-24.6с подтвердил отдельный токен «в» перед «шапке» (VAD/токенизатор не выделил его отдельным словом, хотя «шапке» уже было распознано в правильном падеже) — тот же повторяющийся по кампании паттерн пропуска «в».
- **video3:** CTA — широкий передекод 20.7-22.3с подтвердил тот же пропуск «в» перед «шапке».

После применения правок — проверка на пересечения временных меток слов: пересечений и отрицательных длительностей не найдено ни в одном видео.

`build_words.py`, `asr_batch.py`, `pipeline.py`, `make_subs.py`, `redecode_ts.py`, `loudnorm.py`, `validate.py` унаследованы из `maksim2010` без правок кода (кроме `gen_render.py` — см. выше про `w0`/`h0`).

## Карточки и тайминги

`data1.py`/`data2.py`/`data3.py` — хук (0-2.4...2.6с, акцентный, формулирует боль ЕГЭ-предмета ученика, не пересказ первой фразы) + 8-9 карточек на видео (1-3 слова, кегль 85-95/40-48px) + бегущая подпись (из слов, PT Sans Narrow Bold) + 4 эмфасис-зум окна на ролик. Валидация пройдена (`validate.py`): нет пересечений карточек/хука/зума, последняя карточка заканчивается точно на DURATION, хук закрывается строго до первой карточки, зум-окна не пересекаются.

- video1 (физика, 22 задания по номеру из банка ФИПИ): хук «22 ЗАДАНИЯ ПО ФИЗИКЕ / НЕ УСПЕВАЕШЬ?», 9 карточек, CTA.
- video2 (химия, задача 34, текстовый разбор): хук «ЗАДАЧА 34 ПО ХИМИИ / РЕШАЕШЬ НАУГАД?», 10 карточек, CTA.
- video3 (обществознание, политические режимы, игра на запоминание): хук «ПОЛИТИЧЕСКИЕ РЕЖИМЫ / ВСЕ ПУТАЕШЬ?», 8 карточек, CTA.

Иконка приложения (ЕГЭ ТРЕНАЖЁР) появляется на оба голосовых упоминания в каждом ролике (автоматически по паттерну `тренаж` в `words{N}.json`):
- video1: окна (16.636, 19.636) и (23.42, 25.218)
- video2: окна (15.988, 18.988) и (22.716, 24.6)
- video3: окна (13.972, 16.972) и (20.508, 22.38)

## Громкость

Двухпроходный EBU R128 (`loudnorm.py`, TP-цель −2.0 на обоих проходах, §4.5.1) + финальная проверка TP на готовом AAC-файле. Все три прошли на обычном проходе, лимитер-эскалация не понадобилась:

| видео | pass1 измерено | финальный AAC (после кодирования) |
|---|---|---|
| video1 | I=-18.22 TP=-3.19 LRA=2.10 | I=-14.25 LUFS, TP=-1.86 dBTP |
| video2 | I=-18.05 TP=-4.98 LRA=2.10 | I=-14.11 LUFS, TP=-1.88 dBTP |
| video3 | I=-17.80 TP=-3.42 LRA=3.10 | I=-14.23 LUFS, TP=-1.89 dBTP |

## QA

Стоп-кадры на хук/карточка/иконка/зум/CTA извлечены и просмотрены для всех трёх видео (14 кадров). Хук закрывается строго до старта первой обычной карточки; карточки не вылезают за края кадра, текст не на лице/рту, поля соблюдены; иконка приложения полностью непрозрачна, крупная (280px), справа на уровне головы, не перекрывает лицо, появляется на оба упоминания в каждом ролике; CTA «ссылка в шапке профиля» идентичен во всех трёх; акцент только ледяной голубой, один сет на ролик. Эмфасис-зум отработал корректно на уже-1080p источнике после правки `w0`/`h0` в `gen_render.py` — проверено по длительности рендеров (совпадает с DURATION) и визуально на пиках зум-окон. Дефектов не найдено.

## Файлы в этой папке

`pipeline.py`, `asr_batch.py`, `build_words.py`, `make_subs.py`, `redecode_ts.py`, `loudnorm.py`, `validate.py` — унаследованы от `montage_maksim2010/` без правок кода. `gen_render.py` — правка на имя ASS-файла (`subs_m2110_{i}`) и на явный `w0=1080, h0=1920` в вызове `zoom_segments_filter` (источник уже 1080×1920, не 4K). `data1.py`/`data2.py`/`data3.py` — карточки/хук/эмфасис/длительность. `apply_fixes.py` — ASR-правки. `asr{1,2,3}.json`/`words{1,2,3}.json` — распознавание речи. `subs_m2110_{1,2,3}.ass` — готовые субтитры. `render{1,2,3}.sh` — сгенерированные ffmpeg-скрипты рендера.

Исходные видео (video1/2/3.mp4) и промежуточные/финальные рендеры НЕ архивируются — только код и транскрипты. Готовые ролики лежат в `work/максим2110/максим2110_{1,2,3}.mp4`.
