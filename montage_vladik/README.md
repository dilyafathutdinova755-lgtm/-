# Монтаж «Влад» — 3 ролика (тег `владик`, новая съёмка)

Исходники: релиз с тегом `владик` (без цифры — отдельный от партии
`владик1`). Файлы датированы `15.09` (`Untitled.Video.15.09.{1,2,3}_2160p.mp4`),
необычно тяжёлые (196-224MB против обычных 60-130MB — источник менее
сжат/выше битрейт при том же разрешении 2160×3840). Тот же герой
(Влад), что в партии `владик1`, но новая комната (книжный шкаф,
светлое кресло) и новая одежда (серый свитер вместо чёрной рубашки).
Проверено протоколом §8: sha256 не совпадает ни с одним файлом партий
`владик1`/`vlad`/`vlad2`, три новых сюжета по ASR — не дубль.

**Холодный сет подтверждён замером пикселей**: фон стены даёт
RGB≈160:154:141 (R/B≈1.13), почти идентично известному холодному
кадру `vladik1` (145:137:124, R/B≈1.17). Акцент `#C9F5FF`.

## Сюжеты

1. **Сверил с другом — условие другое?** Выпускники сверяют задания
   ЕГЭ с другом и находят разные версии условия в разных приложениях.
   ЕГЭ Тренажёр держит одну версию задания, одинаковую у каждого, кто
   открывает приложение — обновление формулировки приходит всем сразу,
   без разных версий для разных телефонов.
2. **Теряешь время на расписание?** Выпускники открывают расписание
   занятий на неделю, чтобы понять, что делать сегодня, и теряют время
   на само расписание. ЕГЭ Тренажёр сразу показывает одно дело на
   сегодня без открытия расписания на неделю вперёд — дело меняется
   само на завтра, начать заниматься получается сразу при входе.
3. **Заводишь тетрадь ошибок и бросаешь?** Выпускники переписывают
   ошибки в отдельную тетрадь и забрасывают её через неделю. ЕГЭ
   Тренажёр хранит ошибку прямо в задании без отдельной тетради —
   ошибка остаётся отмеченной сама, без ручного ведения записей, даже
   если прошлую тетрадь бросили на середине.

## Исправленный артефакт ASR

Видео 2: CTA «ссылка на ЕГЭ Тренажёр в **шапки** профиля» → «в
**шапке** профиля» — тот же повторяющийся падежный сбой ASR, что
встречался почти в каждой прошлой партии. Видео 1 и 3 в этот раз
распознались чисто, без похожей ошибки. Правка — только в JSON с
таймкодами речи, звук не трогали.

Результаты — `../vladik/*_smontirovano.mp4`, 1080×1920, 25fps.

## Файлы
| файл | что это |
|---|---|
| `pipeline.py` | генератор ASS (3 слоя, холодный сет) + сегментный эмфасис-зум + окна иконки |
| `data{1,2,3}.py` | HOOK/CARDS/EMPHASIS/DURATION по каждому ролику |
| `subs_vl{1,2,3}.ass` | готовые субтитры |
| `gen_render.py`, `render{1,2,3}.sh` | сборка финального рендера (crop-zoom сегменты + ass + иконка) |
| `loudnorm.py` | двухпроходный EBU R128 + финальная проверка TP на AAC |
| `asr{1,2,3}.json`, `words{1,2,3}.json` | распознавание речи и таймкоды (видео 2 — с правкой) |

Звук — двухпроходный EBU R128 с запасом TP `-2.0` (§4.5.1):

| видео | I (LUFS) | TP на готовом AAC (dBTP) |
|---|---|---|
| 1 | −14.70 | −1.71 |
| 2 | −14.26 | −1.72 |
| 3 | −14.53 | −1.51 |

Все три легли близко к целевым −14 LUFS с комфортным запасом от
потолка −1.0 dBTP.

QA-чеклист §4.6 пройден полностью на всех трёх стоп-кадрами: хук
закрывается до первой карточки, холодный акцент читается раздельно от
белого, карточки не висят дольше 4с, иконка полноразмерная и
непрозрачная и выходит на оба упоминания «тренажёр» в каждом ролике,
бегущая подпись идёт непрерывно одним словом в фиксированном слоте,
эмфасис-зум не выталкивает карточку за края кадра на пике (проверено
отдельно на длинном слове «ОТМЕЧЕННОЙ» в видео 3), CTA единый «ссылка
в шапке профиля».

## Компрессия (§4.7 — эскалация)

Источник необычно детализированный/высокобитрейтный (196-224MB на
~30с при 2160×3840, против обычных 60-130MB в прошлых партиях) — при
дефолтном `crf 23` все три файла вышли за лимит отправки ~30MB
(31.8/35.3/35.2MB). Эскалировано до `crf 27` — уложились в 17.6/19.5/
19.3MB, читаемость текста на стоп-кадре проверена отдельно, не
пострадала.
