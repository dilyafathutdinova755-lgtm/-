# montage_dmitry2010

Монтаж 3 роликов под тегом `дмитрий2010` (холодный сет, кабинет, книжный шкаф, растение).

## Источники

| файл | длительность | release asset |
|---|---|---|
| video1.mp4 | 25.480с | `Untitled.Video.2010.1_2160p.mp4` (87 681 348 байт, sha256 `0611b0de...` по release API) |
| video2.mp4 | 22.360с | `Untitled.Video.2010.2_2160p.mp4` (80 363 013 байт, sha256 `b185d2f6...` по release API) |
| video3.mp4 | 26.120с | `Untitled.Video.2010.3_2160p.mp4` (90 095 228 байт, sha256 `4c8e8120...` по release API) |

Скачаны из релиза `дмитрий2010`, все три совпадают по размеру с release API.

## Комната и герой

Референс-кадры (`ffmpeg -ss 10 -frames:v 1`) сравнены с историческими батчами. Подтверждена знакомая студия: тёмно-синяя рубашка, очки, кабинет с книжным шкафом, картиной с пейзажем и растением — та же линия, что в `dmitry1510`/`dmitry1610`/`дмитрий1710`. Пайплайн унаследован от **`дмитрий1710`** (самый свежий батч этой студии).

## Проверка на дубли (§8)

Длительности всех трёх видео (25.480с, 22.360с, 26.120с) и полные ASR-транскрипты сверены с исторической базой — точных совпадений не найдено. Содержание всех трёх тематически и лексически различно (задание 32 по химии / задание 7 по русскому / налоги по обществознанию, во всех трёх — про дочь, не сына), слово «ссылка» встречается в транскрипте каждого видео ровно один раз — по одному ролику на файл.

## Палитра

Комната и сет холодные, без переключения — продолжение исторической классификации кабинета «дмитрий» (`#C9F5FF`). `pipeline.py` унаследован от `дмитрий1710` без правок.

## ASR-правки

Пайплайн: sherpa-onnx zipformer (ru) + silero VAD → `asr_batch.py` → `build_words.py` → ручная правка через `apply_fixes.py`, каждая неоднозначная правка проверена `redecode_ts.py` перед применением.

- **Все три видео:** `"егэ"` → `"ЕГЭ"` (регистр).
- **video1:** CTA («ссылка на тренажёр в шапке профиля») распознана полностью и чисто, без фиксов кроме регистра.
- **video2:** слово `"водка"` (4.668-5.192с) — явно garbled «вот как» (редекод 4.4-7.8с дал чистые токены ' вот'/' как' на этой же позиции; та же переходная фраза, что в video1 на аналогичном месте), разбито на два слова в существующих границах; `"тотча"` (5.692-5.952с) — garbled «дочь» (несуществующее слово, контекст «вот как ДОЧЬ сама исправляла слово» подтверждён редекодом), исправлено по позиции. CTA — широкий передекод 19.9-22.5с подтвердил отдельный токен «в» перед «шапки» (нуджен на 10мс от сырого редекода, чтобы не пересечься с концом «тренажёр» в этом прогоне выравнивания), «шапки» → «шапке».
- **video3:** то же `"водка"`→«вот как» (5.212-5.608с, редекод 4.9-6.1с подтвердил). CTA («в шапке профиля») распознана полностью и чисто, без фиксов кроме регистра.

После применения правок — проверка на пересечения временных меток слов: пересечений и отрицательных длительностей не найдено ни в одном видео.

`build_words.py`, `asr_batch.py`, `pipeline.py`, `make_subs.py`, `redecode_ts.py`, `loudnorm.py` унаследованы из `дмитрий1710` без правок кода (кроме имени ASS-файла в `gen_render.py`).

## Карточки и тайминги

`data1.py`/`data2.py`/`data3.py` — хук (0-2.6с, акцентный, формулирует боль родителя по конкретному заданию дочери, не пересказ первой фразы) + 8-9 карточек на видео (1-3 слова, кегль 85-95/40-48px) + бегущая подпись (из слов, PT Sans Narrow Bold) + 4 эмфасис-зум окна на ролик. Валидация пройдена (`validate.py`): нет пересечений карточек/хука/зума, последняя карточка заканчивается точно на DURATION, хук закрывается строго до первой карточки.

- video1 (химия, задание 32): хук «ДОЧЬ ЗАВИСАЕТ / НА ЗАДАНИИ 32?», 8 карточек, CTA.
- video2 (русский, задание 7): хук «ДОЧЬ ОШИБАЕТСЯ / В ЗАДАНИИ 7?», 8 карточек, CTA.
- video3 (обществознание, налоги): хук «ПУТАЕТ НАЛОГИ / ПО ОБЩЕСТВОЗНАНИЮ?», 9 карточек, CTA.

Иконка приложения (ЕГЭ ТРЕНАЖЁР) появляется на оба голосовых упоминания в каждом ролике (автоматически по паттерну `тренаж` в `words{N}.json`):
- video1: окна (16.708, 19.708) и (23.972, 25.48)
- video2: окна (13.58, 16.58) и (20.804, 22.36)
- video3: окна (16.564, 19.564) и (24.58, 26.12)

## Громкость

Двухпроходный EBU R128 (`loudnorm.py`, TP-цель −2.0 на обоих проходах, §4.5.1) + финальная проверка TP на готовом AAC-файле. Все три прошли на обычном проходе, лимитер-эскалация не понадобилась:

| видео | pass1 измерено | финальный AAC (после кодирования) |
|---|---|---|
| video1 | I=-17.21 TP=-3.53 LRA=3.30 | I=-14.26 LUFS, TP=-1.84 dBTP |
| video2 | I=-17.21 TP=-3.69 LRA=5.20 | I=-14.48 LUFS, TP=-1.91 dBTP |
| video3 | I=-16.99 TP=-3.37 LRA=5.20 | I=-14.49 LUFS, TP=-1.84 dBTP |

## QA

Стоп-кадры на хук/карточка/иконка/зум/CTA извлечены и просмотрены для всех трёх видео (21 кадр). Хук закрывается строго до старта первой обычной карточки; карточки не вылезают за края кадра, текст не на лице/рту, поля соблюдены; иконка приложения полностью непрозрачна, крупная (280px), справа на уровне головы, не перекрывает лицо, появляется на оба упоминания в каждом ролике; CTA «ссылка в шапке профиля» идентичен во всех трёх; акцент только ледяной голубой, один сет на ролик. Два кадра (video1 на 24.0с, video3 на 16.6с) попали в самое начало fade-in окна иконки (0.03-0.04с после старта 0.32-секундного fade) — переизвлечение из середины тех же окон подтвердило полную непрозрачность, это сэмплинг-артефакт на границе fade, не дефект рендера (тот же паттерн отмечен в `максим2010`/`сергей2010`). Дефектов не найдено.

## Файлы в этой папке

`pipeline.py`, `asr_batch.py`, `build_words.py`, `make_subs.py`, `redecode_ts.py`, `loudnorm.py` — унаследованы от `montage_dmitry1710/` без правок кода. `gen_render.py` — правка на один путь (имя ASS-файла `subs_d2010_{i}`). `data1.py`/`data2.py`/`data3.py` — карточки/хук/эмфасис/длительность. `apply_fixes.py` — ASR-правки. `validate.py` — инлайн-проверка таймингов. `asr{1,2,3}.json`/`words{1,2,3}.json` — распознавание речи. `subs_d2010_{1,2,3}.ass` — готовые субтитры. `render{1,2,3}.sh` — сгенерированные ffmpeg-скрипты рендера.

Исходные видео (video1/2/3.mp4) и промежуточные/финальные рендеры НЕ архивируются — только код и транскрипты. Готовые ролики лежат в `work/дмитрий2010/дмитрий2010_{1,2,3}.mp4`.
