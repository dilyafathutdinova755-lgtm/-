## Технический инцидент: нехватка диска и восстановление шрифтов

В середине задачи (после скачивания исходников, перед ASR) все команды Bash начали падать с ошибкой нехватки места на диске — отказала даже запись harness'ом собственного файла вывода команды. Причина — за сессию накопилось ~20 рабочих папок (`/home/user/-/work/<тег>/`) с необработанными исходниками уже завершённых и заархивированных в git партий (сырые 4K-видео, аудио, промежуточные рендеры), не удалённые после сдачи. Диагностика и исправление:

1. Через `Glob` (не требует записи вывода) подтверждено, что проблема — переполнение конкретной служебной директории harness'а.
2. Пробное `rm` (без видимого вывода, но исполнившееся) освободило место настолько, что `df` снова заработал — показал всего 148K свободных на момент проверки.
3. Для каждой из ~20 папок-кандидатов на удаление сверено наличие соответствующего `montage_<тег>/` в git — все подтверждены как уже заархивированные. Удалены только эти, сырые видео не нужны (архивы содержат код и транскрипты, не видео, доставка уже отправлена пользователю ранее). Текущая, ещё не сданная партия (на тот момент только что скачанные `video{1,2,3}.mp4` этого тега) не трогалась.
4. После удаления свободно 23G — с большим запасом на эту партию.

Побочный эффект: вместе с рабочими папками удалились и шрифты `GolosText-Black.ttf` / `PTSansNarrow-Bold.ttf`, которые существовали только как локальные файлы внутри каждой папки (не были закоммичены в git и не были установлены в систему постоянно). Пайплайн ожидает их по точному имени семейства шрифта («Golos Text Black», «PT Sans Narrow») через fontconfig.

Восстановление:
- Переменный шрифт Golos Text скачан из `google/fonts` (raw.githubusercontent.com), статический вес 900 (Black) вырезан через `fonttools varLib.instancer`.
- PT Sans Narrow Bold получен через Google Fonts CSS2 API (`fonts.googleapis.com/css2`) — прямая ссылка на `fonts.gstatic.com`, т.к. точное имя файла в `google/fonts` репозитории не совпало с ожидаемым (`PTSansNarrow-Bold.ttf` дал 404).
- Оба шрифта переименованы через `fontTools.ttLib` (name table, nameID 1/2/4/6) под точные строки, которые ожидает `pipeline.py`: Golos → family «Golos Text Black», subfamily «Regular»; PT Sans Narrow → family «PT Sans Narrow», subfamily «Regular» (хотя физически это bold-начертание — так и было в оригинальной паре файлов, подтверждено сверкой со старым PT Sans Narrow Bold: family у него уже было «PT Sans Narrow», просто subfamily «Bold», переименовано на «Regular» для совпадения с ASS-стилем `Bold=0`).
- Полная кириллица подтверждена программно (`getBestCmap()`) для обоих файлов перед использованием — пропусков нет.
- Установлены в `~/.fonts` + `fc-cache -f` (фонтконфиг теперь резолвит оба имени верно), локальная копия также положена в `fonts/` этой партии для PIL-замера текста в `pipeline.py`, и в `/home/user/-/work/fonts/` — общее место для переиспользования будущими партиями без повторного скачивания.
- Корректность рендера подтверждена визуально на стоп-кадрах всех трёх видео (см. QA) — карточки в фирменном Golos Text Black, бегущая подпись в PT Sans Narrow, различие начертаний видно на глаз, как и требуется.
