## Техническое примечание: найден и исправлен баг в loudnorm.py

На video3 финальная проверка TP на готовом AAC-файле изначально провалилась катастрофически — **+0.62 dBTP** вместо требуемых ≤ −1.0 dBTP (пик реально клиппировал выше 0 dBFS). Причина оказалась в двух независимых проблемах унаследованного `loudnorm.py`:

1. **Скрипт жёстко форсировал `linear=true`** на втором проходе loudnorm, не читая поле `normalization_type` из JSON первого прохода. Для video3 первый проход сам определил `"normalization_type": "dynamic"` (это явный сигнал ffmpeg, что линейный режим для данного файла рискует превысить целевой TP), но правка это игнорировала. Один нетипично резкий пиковый транзиент в конце записи (~22.1-22.4с) при линейном усилении (+7.62 дБ для выхода на -14 LUFS) многократно усиливал AAC-овершут сверх обычных 0.3-0.9 дБ, наблюдавшихся в прошлых батчах.
2. Попытка форсировать `linear=false` вместо этого ничего не изменила — встроенный динамический лимитер ffmpeg внутри `loudnorm` тоже не справился с этим конкретным транзиентом. Пришлось добавить отдельный true-peak лимитер (`alimiter`) после `loudnorm` в цепочке фильтров, но первая попытка с `alimiter=limit=0.631` (без явного `level=disabled`) не сработала: по умолчанию `alimiter`'s `level=1` **авто-нормализует звук обратно к лимиту** (поднимает громкость до потолка), полностью сводя на нет цель ограничения. Добавление `level=disabled` исправило это окончательно.

`loudnorm.py` переписан:
- `apply()` теперь читает `normalization_type` из измерения первого прохода и передаёт `linear=true`/`false` соответственно, а не форсирует `linear=true` всегда.
- Добавлена условная эскалация: если обычный проход (без лимитера) не проходит финальную TP-проверку на AAC, скрипт автоматически повторяет кодирование с `alimiter` на всё более низком потолке (−3.0 → −4.0 → −5.0 дБFS, с `level=disabled`), пока проверка не пройдёт.
- Лимитер применяется **только** к тем видео, которым он реально нужен — video1 и video2 кодируются обычным проходом без потери громкости (их показатели после правки идентичны тому, что было бы без бага: I≈-14.8/-14.6 LUFS).

Для video3 это означает итоговую интегральную громкость -15.32 LUFS вместо целевых -14 — приемлемое отклонение по правилу §4.5.1 («иногда исходник физически не может дотянуть до -14 в линейном режиме, упираясь в потолок по TP — это нормальная характеристика конкретной записи»), не брак.

Полный чеклист §4.6 пройден для всех трёх видео (проверка стоп-кадрами: хук, карточка+бегущая подпись, иконка, пик эмфасис-зума, CTA). Хук закрывается до старта первой карточки во всех трёх (2.90с), целиком акцентным цветом (холодный #C9F5FF). Карточки не превышают 4с, межстрочный интервал плотный, акцентная строка крупнее белой с тонкой обводкой. Иконка «ЕГЭ Тренажёр» появляется на оба голосовых упоминания в каждом ролике, 100% непрозрачность, справа на уровне головы, не задевает лицо. Бегущая подпись непрерывна, в одном слоте, по одному слову. Эмфасис-зум (4 фразы на ролик, ×1.14) проверен стоп-кадрами на пике — карточки не уезжают за края кадра ни в одном случае.
